# Polar Marketing design system

**This is the single source of truth for design.** `brand/DESIGN.md` is a long, inspirational reference (voice, mood, screen sketches, QA ideas). Read it for context only. **On any conflict, this document wins.** Where the code does not yet match a decision here, it is listed under "Known deviations" (the code is fixed later; the decision stays).

Machine-readable tokens live in `brand/tokens.css` (generated by `scripts/brand-tokens.mjs`, never edit by hand) and `brand/tokens.json`. Component classes live in `brand/components.css`. Theme switching lives in `brand/theme.js`. `brand/ADOPTION.md` explains how to wire a page.

Personality: minimal, playful, confident, approachable. Scandinavian minimalism with one lime accent. Audience: small businesses in Tenerife. Mobile first.

## 1. Page contract (every Polar-owned page)

1. In `<head>`, first: `<script src="/brand/theme.js"></script>` (blocking, sets `data-theme` before paint).
2. Then `<link rel="stylesheet" href="/brand/tokens.css">` and `/brand/components.css`, then page styles.
3. `<meta name="viewport" content="width=device-width, initial-scale=1">` and `<meta name="theme-color">` (theme.js updates it).
4. `<html lang="es|en">` kept in sync with the chosen language. Wrap content in `class="cr-root"` unless the page sets the same base styles itself.
5. Page CSS uses **only token variables**. No hard-coded hex except the exceptions in section 2.4.

### 2.2 Usage rules

- Lime: primary buttons, active navigation indicator, selected chips/language, key figures, small highlights. Never a whole bar, never body text on a light background.
- Text on lime is always `--on-brand`. Lime is never used as text on `--bg`/`--surface` in light mode (contrast about 1.2:1); use `--brand-ink`.
- Status is never colour alone: every badge carries a word (and ideally an icon).
- Photographs stay natural in both themes; never invert or filter them.
- Dark mode uses distinct surfaces (`--bg` < `--surface` < `--surface-2`), subtle borders, no pure white background, shadows removed.

### 2.3 Contrast (WCAG 2.2 AA, validate when changing tokens)

- Body and label text: `--ink` or `--ink-2` only. These pass AA on `--bg`, `--surface`, `--surface-2` in both themes.
- `--ink-3` is below 4.5:1 on light surfaces. Use it only for decorative or non-essential marks (placeholders of disabled controls, separators), never for text the user must read. `src/styles.css` therefore aliases `--ink-3` to `--ink-2`; new code should simply use `--ink-2`.
- Large text (18.66px bold / 24px) needs 3:1, UI components and focus rings 3:1.
- Disabled controls: `opacity: .45` plus `cursor: not-allowed`; the label must stay legible.

### 2.4 Allowed hard-coded colours

Only: the logo tile background `#fff` (`.pm-logo`), the modal scrim `rgba(0,0,0,.42)`, third-party brand marks in share sheets (Instagram, Facebook, X, YouTube), wallet pass colours, and the user's own loyalty-card design colours. Nothing else.

## 3. Typography

- **Display: Bricolage Grotesque** (600/700/800) for headings, large figures, brand name, sheet titles. Variable `--font-display`.
- **Body and UI: Figtree** (400/500/600/700) for everything else, including buttons, nav, forms, tables. Variable `--font-body` (alias `--font-sans`).
- **Mono is retired.** `--font-mono` is Figtree; figures use `font-variant-numeric: tabular-nums` (`.num`, `.tabular`, `.data`).
- Fallbacks are already in the tokens (`"Avenir Next","Segoe UI",system-ui` / `"Segoe UI",system-ui`). Same fonts in both themes.
- **Loading: self-hosted only on Polar's own pages** (woff2 under `/brand/fonts/`, `@font-face` with `font-display: swap`, subsets latin + latin-ext). No Google Fonts link on Polar's own pages (privacy: no third-party requests). Until the files exist, pages render with the fallback stack and that is acceptable.

## 4. Spacing, radius, shadow, motion

- **Spacing** (4px base): `--space-1` 4, `-2` 8, `-3` 12, `-4` 16, `-5` 24, `-6` 32, `-7` 48, `-8` 64, `-9` 80. Page side padding 16px on phones (plus safe-area), 24-32px from 900px. Form field gap 16, card padding 16-24, section gap 24-32.
- **Radius** (final values are those in `tokens.css`, not the smaller ones in DESIGN.md): `--radius-xs` 4, `-sm` 12 (logo tile, small tags), `-md` 16 (inputs, boxes), `-lg` 24 (cards), `-xl` 32 (hero, large panels), `-pill` 999 (buttons, chips, badges, nav pills). Bottom sheets: 28px top corners.
- **Shadow:** `--shadow-card` on cards, `--shadow-pop` on floating layers. Separation in dark mode comes from surface colour and `--line`, not shadow.
- **Touch sizes:** `--tap` 48px (default control), `--tap-lg` 56px (inputs, large buttons). Absolute minimum 44x44 for anything tappable.
- **Motion:** `--duration-fast` 120ms, `-normal` 200ms, `-slow` 280ms, `--ease-standard`. Allowed: colour/background fades, 0.98 press scale, sheet slide (250ms), spinner. No parallax, no looping decoration. `prefers-reduced-motion: reduce` collapses all durations (already in `tokens.css`; do not override).

## 5. Components

All component classes are prefixed `cr-` (legacy name kept for compatibility) except logo, icon and theme (`pm-`). The studio (`src/styles.css`) has equivalent short classes (`.btn`, `.input`, `.chip`, `.card`); they must look identical. New standalone pages use `cr-*`; React studio code uses the `src/core/ui.tsx` kit.

- **`.cr-btn`** is always a pill, min-height 48px, weight 700, 2px transparent border. Variants: `--primary` (lime, one per screen region), `--soft` (brand-soft), `--secondary` (surface + `--line` border), `--outline` (transparent + `--line-strong`), `--tertiary` (text only), `--danger` (bad-soft + bad border, for destructive actions). Sizes: default 48, `--lg` 56, `--block` full width. States: hover (token hover), `:active` scale .98, `[disabled]`, `.is-loading` (spinner, keep width). Labels are verbs ("Create my website", "Post it").
- **`.cr-input`** (+ `.cr-field`, `.cr-label`, `.cr-hint`): filled `--surface-2`, 2px transparent border, radius `--radius-md`, height 56. Focus: `--surface` fill and `--brand` border plus the focus ring. Error: `.cr-field--error` (bad border, hint in `--bad` with an explanatory sentence). Every input has a visible `<label>`; placeholders never replace labels. `textarea.cr-input` min 112px.
- **`.cr-chip`**: selectable pill wrapping a visually hidden radio/checkbox; selected = lime with `--on-brand`.
- **`.cr-badge`** (`--good|--warn|--bad|--info`): soft pill, always text, optional 14px icon.
- **`.cr-card`**: surface, radius 24, padding 24 (16 on phones), `--shadow-card`. `.cr-card--basalt`: solid basalt hero panel, radius 32. Card titles use the display font.
- **`.cr-post`**: generated-post preview (112px image + text; stacks under 420px).
- **`.pm-logo`** (`--lg`): the supplied bear logo always on a white tile (also in dark mode), 40px or 96px. `/brand/logo/polar-mark.png` compact, `polar-logo.png` large. Never redraw, recolour, stretch or place on lime/photos without the tile.
- **`.pm-ic`** (`--sm` 16, default 20, `--lg` 24): icon, see section 7.
- **`.pm-theme`**: Light/Dark/System radiogroup (section 8).
- **Studio-only** (in `src/styles.css`): `.tabs/.tab` (selected = bold + 3px lime underline), `.tab-count`, `.mode-pill`, `.eyebrow`, `.box`, `.grid-2/.grid-3/.split`, `.stack`, `.row`. Portal-only: `.sheet`, `.lsheet`, `.mrow`, `.nav`, `.toast`.
- **Dialogs and sheets:** `role="dialog" aria-modal="true" aria-labelledby`, scrim `rgba(0,0,0,.42)`, `Escape` closes, focus moves to the title (`tabindex="-1"`) on open and returns to the trigger on close, safe-area bottom padding, max-width 560-600px centred.
- **Toasts:** inverse (`--ink` on `--bg`), above the bottom nav, `role="status"`, text states a fact that already happened.
- **Empty / loading / error states:** every list has all three: one sentence of what and what next, a single primary action, never a blank area.

## 6. Navigation

One information architecture, three surfaces. Destination names are the same everywhere; do not invent a separate concept per screen size.

### 6.1 Owner dashboard (studio, `src/App.tsx`)

Left rail (256px, `.rail`, collapses behind a menu button under 860px): logo tile + "Polar Marketing", then groups ("Your business", "Extra tools", "More extra tools") of `.nav-item` pills (min-height 44, active = lime pill with `--on-brand`, `aria-current="page"`). Footer holds the full-width theme selector. Top bar: menu button (mobile), mode pill (live/demo), theme selector (hidden under 860px). Routes are hash-based (`#route`, `useRoute`, `navigate`). The rail `nav` has an accessible name.

### 6.2 Client portal (`server/portal.html`), phone first

**Bottom nav: exactly 5 items, in this order, never more.** Fixed, max-width 560 centred, safe-area padding, content padded so nothing hides behind it.

| # | ES label | EN label | Icon (Lucide) | Opens |
| --- | --- | --- | --- | --- |
| 1 | Asistente | Assistant | `message-square` | Chat/assistant home |
| 2 | Contenido | Content | `layout-grid` | Posts, with a Posts \| Vídeos / Videos segmented toggle in the view header; badge for items awaiting review |
| 3 | Web | Website | `globe` | Website (AI-built or own site) |
| 4 | Fidelidad | Loyalty | `credit-card` | Loyalty card |
| 5 | Más | More | `ellipsis` | The Más sheet |

Each item: 24px icon in a 56x32 pill, 11px/600 label under it. **On phones (max-width 768px) the bar is slimmer and more refined:** 60px tall instead of 85px, a 50x30 pill, 1.75 stroke icons, 12px/600 labels with 0.01em tracking on a 1.2 line height, and a 0.94 press on the active pill. The tap area is the button plus 4px above and below (55px), so it keeps the 44px minimum without making the bar grow, and the labels never wrap. Above 768px the bar keeps the roomier look. Active item (`aria-current="page"`): pill filled `--brand`, icon `--on-brand`, label `--ink`; inactive label uses muted ink. Focus ring on the pill. Group highlighting: Contenido is active for posts and videos; Más is active for Reservas, Carta, Gastos. Count badges are lime with `--on-brand`, 17px min, capped sensibly.

### 6.3 The Más sheet

Bottom sheet (`aria-haspopup="dialog"` on the trigger). Title "Más" / "More". Rows (`.mrow`, 56px high, 40px circular icon well, label, trailing `chevron-right`), in this order:

1. Reservas / Bookings (pending count badge)
2. Carta / Menu (only when the business enabled it)
3. Gastos / Expenses (only when enabled)
4. Ajustes / Settings
5. Ayuda y soporte / Help and support (mailto link)
6. Cerrar sesión / Sign out (last, separated)

New portal features go inside Más or inside an existing section. They never become a sixth bottom item.

### 6.4 Public pages

Landing, signup, home, loyalty, booking and menu pages are single-column, with the language toggle (ES/EN chips) and theme selector in the header or footer, no bottom nav. Secondary screens have a consistent back control (`arrow-left`).

## 7. Icons: Lucide, only Lucide

Lucide (ISC licence) is the **only** icon set. Never emoji, Unicode symbols (check marks, arrows, stars), Bootstrap Icons or Font Awesome as interface icons. (Generated client websites are separate and follow their own brief.)

**No CDN on Polar's own pages.** Include icons as inline SVG copied verbatim from Lucide:

- Source the `<svg>` path data from the `lucide-static` package (or lucide.dev) at build/edit time and paste it; do not hand-draw look-alikes. Keep the Lucide name as the sprite id/key.
- Markup: `<svg class="pm-ic" viewBox="0 0 24 24" aria-hidden="true"><path d="..."/></svg>`; `fill: none; stroke: currentColor; stroke-linecap: round; stroke-linejoin: round`.
- **Stroke width 1.75** (set once in `.pm-ic` via `stroke-width: 1.75`; never per icon). Colour always `currentColor`, so icons follow text and theme.
- **Sizes:** 16 (`--sm`, inside text/badges), 20 (default, buttons, rows), 24 (`--lg`, bottom nav and sheet wells), 32 (feature/empty states). The hit area around an icon button is at least 44x44.
- HTML pages: one hidden sprite per page (`<svg width="0" height="0" style="position:absolute" aria-hidden="true"><symbol id="i-name" viewBox="0 0 24 24">...</symbol></svg>`) used with `<use href="#i-name"/>`; ship only icons that page uses. React: the `Icon` map in `src/core/ui.tsx` (one shared map; do not add a second set).
- Accessibility: decorative icons `aria-hidden="true"`; icon-only buttons get `aria-label` (and `title`); meaningful standalone icons use `role="img"` + `aria-label`.
- Active/highlight state uses the pill or `--brand-ink`, not a different icon.

## 8. Theming: light, dark, system

- `brand/theme.js` is the only theme mechanism. It sets `<html data-theme="light|dark">` (the effective theme) and `data-theme-pref="light|dark|system"` (the choice), stores an explicit choice in `localStorage` key **`polar-theme`** (absent = system), follows `prefers-color-scheme` live while on system, updates `meta[name=theme-color]` (`#d7ff64` light, `#0a0a0a` dark) and fires the `polar-theme` window event.
- API: `PolarTheme.get()`, `PolarTheme.set("light"|"dark"|"system")`, `PolarTheme.mount(el, lang)` (renders the `.pm-theme` radiogroup, labels Claro/Oscuro/Sistema or Light/Dark/System).
- CSS keys off `[data-theme="dark"]` (tokens.css also has a no-JS `prefers-color-scheme` fallback). Never branch on `prefers-color-scheme` in page CSS; override with `:root[data-theme="dark"] .x` if a component truly needs it.
- Every component must work in both themes (backgrounds, inputs, borders, sheets, scrims, badges, empty states). Theme change must not shift layout.
- Every page offers the Light/Dark/System selector somewhere reachable (settings panel, footer or rail).

## 9. Accessibility (WCAG 2.2 AA)

- **Focus ring:** `outline: 2px solid var(--ink)`, `outline-offset: 3px` on `:focus-visible` for every interactive element, both themes (inputs additionally show the brand border). Never `outline: none` without a replacement. Nav items show the ring on the pill.
- **Touch targets:** at least 44x44 CSS px, 48 default, 56 for inputs and primary mobile actions; at least 8px between neighbours.
- **Contrast:** section 2.3. Re-check any new colour pairing in both themes; lime never carries white text.
- Semantic HTML first (`nav`, `main`, `button`, `label`). One `h1` per page. `aria-current` for current nav item, `aria-pressed` for toggles, `role="radiogroup"` for segmented choices, `role="alert"` for form errors, `role="status"` for async success.
- Errors are linked to their input (`aria-describedby`) and say what happened and what to do; entered values are preserved.
- Keyboard: everything reachable and operable, Escape closes sheets, no focus traps except modal sheets (which restore focus).
- Respect zoom and text scaling to 200%; no horizontal scroll at 320px; support `prefers-reduced-motion`.
- Do not rely on colour, position or icon alone; every icon-only control has a name. `lang` attribute matches the visible language.

## 10. Copy tone and languages

- Voice: clear, friendly, direct, encouraging, professional. No jargon, no marketing speak, at most one exclamation mark per screen and usually none. Prefer Spanish `tú` form (as the portal does: "Pulsa Guardar").
- Buttons are verbs naming the result: "Create my website", "Post it", "Try again", "Crear mi web", "Publicar". Avoid "Submit", "Proceed", "OK" alone.
- Errors: what happened + what to do next ("We couldn't upload your photo. Check your connection and try again."). Never blame the user, never show stack traces or provider names.
- Success messages appear only after the action truly succeeded and are specific ("Your post is scheduled for 10:00").
- **Spanish is the default** (the portal starts in `es`; landing and home start from the browser language, `es` unless it says otherwise); English is fully supported. Every user-facing string exists in both (see `docs/conventions.md`). Language toggle is two chips, ES and EN, `aria-pressed`, persisted as `polar:lang`.
- Prices are shown in euros with the tax stated: "Precios al mes, IGIC (7 %) no incluido." / "Prices per month, excluding IGIC (7%)." Format with `Intl` (`es-ES` for Spanish UI, `en-IE` for English), EUR, no decimals when the amount is whole.

## 11. Known deviations (code vs. this document)

These are decided, not accepted. Fix opportunistically; do not copy them into new code.

1. **Icon stroke:** `components.css` `.pm-ic` uses `stroke-width: 2`; the portal sprite uses 2 and 2.2 (the phone nav overrides its own icons to 1.75); `ui.tsx` and `src/modules/polar-icons.tsx` use 2 (`.pm-icon`). Decision is 1.75.
2. **Icons are not verbatim Lucide:** `ui.tsx` `ICONS` is "Lucide-style", hand-simplified; the portal has about 50 hand-written `<symbol>`s with custom names (`i-chat`, `i-grid`, `i-card`, `i-more`, `i-cal`...). Two parallel icon sets exist in the studio (`ui.tsx` `Icon` and `polar-icons.tsx`). Portal nav currently uses `chat`, `grid`, `globe`, `card`, `more` shapes rather than the Lucide names in 6.2.
3. **Fonts not self-hosted:** `index.html` (studio) loads Google Fonts; the privacy note in `docs/README.md` says Polar's own public pages load none. The portal, signup, landing and home pages load no font files, so Bricolage Grotesque and Figtree only render where installed; they currently show the system fallback. `server/share.mjs` also links Google Fonts (Inter, Inter Tight), which contradicts "Figtree/Bricolage; Inter retired".
4. **Radius mismatch:** `brand/DESIGN.md` 7.1 lists sm 8 / md 12 / lg 16 / xl 24; `tokens.css` ships 12 / 16 / 24 / 32. Tokens win; `DESIGN.md` is stale on this.
5. **`--ink-3`** fails AA on light surfaces; `src/styles.css` aliases it to `--ink-2` to hide this. Portal and public pages may still use the original value for text.
6. **Duplicate component vocabularies:** studio `.btn/.input/.chip/.card` vs `cr-*`; portal `.primary/.cbtn/.mrow/.sheet`. Visual parity is required, class unification is not yet done. `.cr-btn--soft` and `.cr-btn--secondary` differ slightly from studio `.btn-ghost/.btn-secondary` (border colour `--line` vs `--line-strong`).
7. **Portal nav:** on phones it matches 6.2 (12px labels, 60px bar, 1.75 stroke); above 768px the bar is the older, roomier one (11px labels, 85px). The Contenido Posts | Videos toggle has not been checked against 6.2.
8. **Portal nav focus ring** is drawn on the pill (50x30 on phones, 56x32 above), not on the full tap area.
9. **Studio loyalty "Stamp icon" field** invites an emoji; this is user content for a card design (allowed), not an interface icon.
10. **Studio storage keys:** records use `localStorage` prefix `isla:` (`src/core/store.ts`), a leftover name. Language keys `crier:lang` and `isla:lang` are still read as fallbacks (portal and signup read only `polar:lang` and `crier:lang`).
11. **Hard-coded colours** remain in portal share-sheet brand tiles (allowed, 2.4) and possibly in older modules under `src/modules/*.css`; audit with a grep for `#` hex outside `tokens.css`.
12. **Generated client sites** use Bootstrap, Bootstrap Icons and jsDelivr by design (`server/webpage.mjs`); they are outside this design system, except that the site-design prompt is given `tokens.css` as a palette hint.
